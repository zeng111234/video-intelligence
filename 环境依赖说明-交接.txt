VideoInsight 环境依赖说明
=========================

文档用途
--------
本文档用于公司接手 VideoInsight 源码后的环境准备、源码启动、Windows EXE 打包和服务器控制层维护。
内容依据当前源码目录和依赖清单整理，日期：2026-09-11。

安全边界
--------
1. 本文件不包含任何真实密码、API Key、Token、Cookie、SSH 私钥或 .env 内容。
2. 不要把当前电脑的 .env、数据库、浏览器登录目录、客户媒体、运行日志或 SSH 私钥复制给公司。
3. 公司应在自己的密码库或密钥管理系统中创建并保存新凭据，再按交接文档配置。
4. 下面出现的环境变量名称只是配置项名称，不代表当前已经拥有对应服务权限。

一、项目组成
------------

正式源码入口：
- 后端：project/backend/，FastAPI 应用，开发端口 2001。
- 前端：project/frontend/，React + Vite + Electron，开发端口 1001。
- 共享业务代码：src/。
- Windows 一键启动：根目录 start.bat。
- 全服务启动脚本：scripts/start_all_services.ps1。
- Windows 安装包构建：scripts/build_windows_installer.ps1。
- 控制层服务：deploy/control-plane/，用于公司服务器上的登录、积分、激活码和云端能力。

正式源码开发入口是 React/FastAPI；根目录 app.py 和 app_pages/ 属于 legacy Streamlit 入口，仅用于历史追溯，不是当前 Windows 客户端的正式启动入口。

二、Windows 源码开发环境
-------------------------

必需软件
~~~~~~~~

1. Windows 10/11，建议 64 位。
2. Python 3.12 或更高版本。
3. Node.js 18 或更高版本，建议使用 Node.js LTS。
4. npm，随 Node.js 一起安装。
5. PowerShell 5.1 或 PowerShell 7。
6. FFmpeg 和 FFprobe；本地视频转码、剪辑、媒体校验需要。两者应来自同一发行目录。
7. Git；仅源码协作和版本管理需要。

可选软件
~~~~~~~~

1. Google Chrome 或 Microsoft Edge：关键词发现、平台浏览器自动化需要；普通本地启动不一定依赖。
2. Android SDK Platform Tools/ADB、Appium 和 UiAutomator2：只有手机执行器功能需要。
3. 具备 CUDA 的 NVIDIA 显卡及对应驱动：只有本地 faster-whisper 或本地数字人模型需要；CPU 可以运行，但速度和内存占用会明显不同。
4. Visual Studio Build Tools：只有某些没有预编译轮子的 Python 包需要本地编译时才需要，当前常规 Windows 安装通常不需要。

~~~~~~~~~~~~~~~~~~

以下是本次整理时当前电脑检测到的版本，不是强制锁定版本：
- Python：3.12.3
- 项目 .venv Python：3.12.3
- Node.js：v24.15.0
- npm：11.12.1
- FFmpeg：8.1.2 essentials build
- FFprobe：8.1.2 essentials build

项目真正的兼容下限由启动脚本约束：Python >= 3.12，Node.js >= 18。若要复现发布环境，优先使用公司批准的 Node.js LTS 和 Python 3.12，不要因为当前电脑版本较新就直接把版本升级到未知版本。

五、FFmpeg 和媒体工具
---------------------

根目录 packages.txt 只声明了：
- ffmpeg

实际运行需要同时能够找到：
- ffmpeg.exe
- ffprobe.exe

检查命令：

    ffmpeg -version
    ffprobe -version

Windows 打包脚本还会校验媒体工具发行目录中的 LICENSE、README.txt、ffmpeg.exe、ffprobe.exe，并与 config/windows-media-tools.sha256 比对。打包时不要随意替换单个 ffmpeg.exe 或 ffprobe.exe。

若只是运行已生成的正式 EXE，媒体工具通常已经随安装包后端一起打包；若是源码开发或重新打包，仍必须准备系统 FFmpeg/FFprobe。

六、首次源码启动
-----------------

推荐方式：

    双击根目录 start.bat

或者在 PowerShell 执行：

    .\scripts\start_all_services.ps1

启动脚本的实际行为：
1. 检查 Python >= 3.12 和 Node.js >= 18。
2. 缺少运行时且电脑具备 winget 时，尝试安装 Python 3.12 和 Node.js LTS；失败后停止，不会无限重试。
3. 创建根目录 .venv。
4. 安装 requirements.txt 和 project/backend/requirements.txt。
5. 按 project/frontend/package-lock.json 执行 npm ci。
6. 若根目录没有 .env，则从 .env.example 创建一份无密钥配置。
7. 检测 FFmpeg、Chrome/Edge，并启动本地后端和前端。

启动成功后：
- 前端：http://localhost:1001
- 后端健康检查：http://localhost:2001/health
- 后端接口文档：http://localhost:2001/docs

手动启动后端：

    $env:PYTHONPATH = (Get-Location).Path
    .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 2001

手动启动前端：

    cd project/frontend
    npm run dev

七、配置文件和环境变量
-----------------------

配置模板：
- 根目录 .env.example：源码启动的完整配置模板。
- project/backend/.env.example：后端目录兼容模板。
- deploy/control-plane/.env.example：服务器控制层配置模板。

源码启动时优先使用根目录 .env；如果没有根目录 .env，后端兼容读取 project/backend/.env。正式 Windows 安装包不读取外部 .env，供应商密钥应放在公司控制层，不应打入安装包。

常见配置类别如下，仅填写公司自己的值：
- 应用安全：APP_SECRET_KEY、ADMIN_PASSWORD、API_KEY。
- 本地服务：BACKEND_PORT、FRONTEND_PORT、DATABASE_PATH。
- 转写：ASR_MODE、WHISPER_MODEL、WHISPER_DEVICE。
- 视频剪辑：VIDEO_EDITOR_PROVIDER_MODE、VIDEO_EDITOR_PRICE_VERSION、VIDEO_EDITOR_QUOTE_TTL_SECONDS。
- 公司控制层：VIDEOINSIGHT_CONTROL_PLANE_ENABLED、VIDEOINSIGHT_CONTROL_PLANE_URL、CONTROL_PLANE_CA_BUNDLE。
- 文案、数字人、图片、素材搜索和平台发布：按照 .env.example 中对应的 *_MODE、*_URL、*_API_KEY、*_TOKEN 配置。

交接时要特别注意：
1. 只复制 .env.example，不复制当前电脑的 .env。
2. 阿里云、DeepSeek、个人模型、个人平台账号和个人 SSH 凭据不随源码交付。
3. 公司供应商密钥由公司管理员重新申请，并通过密码库、服务器环境变量或 RAM/服务账号注入。
4. 只填密钥但不切换对应 *_MODE，不会自动启用真实云服务。
5. 真实供应商调用、视频生成、平台发布和可能扣费的操作必须由公司确认后开启。

八、源码测试和质量检查
-----------------------

前端测试和构建：

    cd project/frontend
    npm test
    npm run test:update
    npx tsc --noEmit
    npm run build

Python 测试和静态检查：

    cd ..\..
    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m ruff check .
    .\.venv\Scripts\python.exe -m compileall -q app.py app_pages src scripts tests

这些检查通过只代表代码和构建门通过，不等于已经完成真实视频、页面播放、下载、云端任务或生产服务器验收。涉及视频剪辑时还要按 COMPANY_HANDOFF.md 的正式验收链路验证。

九、Windows EXE 打包环境
------------------------

重新打包除了源码开发依赖，还需要：
1. Python 3.12+ 和根目录 .venv。
2. requirements-build.txt 中的 PyInstaller 6.15.0。
3. Node.js >= 18、npm 和前端锁文件依赖。
4. FFmpeg、FFprobe 及其发行目录中的许可证和说明文件。
5. config/windows-media-tools.sha256 校验清单。
6. 足够的磁盘空间和 Windows Defender/杀毒软件允许构建目录读写。

推荐构建前先通过检查，再执行：

    .\scripts\build_windows_installer.ps1 -Version <new-version>

构建脚本会执行前端类型检查、前端测试、桌面更新测试、Python 发布测试、Vite 构建、PyInstaller 打包和 electron-builder 安装包构建。

构建完成后必须检查：
- 安装包能在干净 Windows 电脑双击安装；
- 前端页面能打开；
- 后端健康检查成功；
- FFmpeg/FFprobe 实际可用；
- 登录、激活码、管理员页面和目标剪辑链路符合当前交接范围；
- 安装包 SHA256 已记录在交接文档；
- 安装包未包含 .env、数据库、客户媒体、日志、浏览器用户目录或真实密钥。

十、服务器控制层环境
---------------------

服务器控制层位于 deploy/control-plane/，当前采用 FastAPI + Uvicorn 原生 systemd 服务方式。不要仅因为目录中存在 Dockerfile 就自行把现有服务切换为 Docker，也不要修改其他域名或服务。

服务器侧基本依赖：
- Linux 服务器，systemd。
- Python 3.12 兼容运行时，建议使用项目维护的虚拟环境或离线运行时。
- deploy/control-plane/requirements.txt 中的 FastAPI、Uvicorn、Pydantic、HTTPX、python-multipart、edge-tts、jieba。
- SQLite 数据库和备份目录，实际路径以服务器 unit 和环境文件为准。
- HTTPS 反向代理/域名配置，正式桌面端只连接 HTTPS 控制层地址。
- 如启用云端转写、剪辑、数字人或文案服务，供应商密钥只放服务器环境，不放桌面端。

控制层依赖版本：
- fastapi==0.139.2
- uvicorn[standard]==0.51.0
- pydantic==2.13.4
- httpx==0.28.1
- python-multipart==0.0.32
- edge-tts==7.2.8
- jieba==0.42.1

服务器启动前必须先阅读 COMPANY_HANDOFF.md 的“服务器维护 SSH 命令手册”，确认服务名、WorkingDirectory、EnvironmentFile、数据库路径、备份策略和回滚目录。不要把服务器密码、私钥或 .env 真实内容写入此文件。

十二、故障排查顺序
-------------------

1. 先检查 Python、Node.js、npm、FFmpeg、FFprobe 是否在 PATH 中。
2. 再检查端口 1001、2001 是否被旧进程占用。
3. 再查看 data/logs/services/ 下的启动日志，不要直接重复发起可能计费的云端任务。
4. Python 依赖问题先确认 .venv 是否为当前源码目录创建，再按两份 requirements 文件重新安装。
5. 前端问题先确认 package.json 与 package-lock.json 属于同一版本，再运行 npm ci。
6. 浏览器自动化问题保留登录、验证码和人工授权边界，不要把浏览器 Cookie 或用户目录复制给公司。
7. 服务器问题按 COMPANY_HANDOFF.md 的 SSH 手册执行只读检查，再决定是否重启或回滚。

完成环境接管后，应把实际使用的 Python、Node.js、FFmpeg、数据库、控制层版本和公司密钥指纹补充到公司的内部资产台账；不要回写任何私钥正文或真实 Token。
