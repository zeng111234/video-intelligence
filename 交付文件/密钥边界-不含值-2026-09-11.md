# 密钥与个人数据边界清单（不含任何值）

更新时间：2026-09-11

本清单只记录变量名、用途和处理建议，不记录、不复制、不展示任何密钥值。变量名本身不能证明账号所有权；“个人/公司”必须以账单主体、注册邮箱、公司管理员或密钥管理系统为准。

## A. 绝对不随源码包交付

当前开发机发现根目录存在真实 `.env` 和 `.env.production`。它们应留在开发机或在移交前单独备份后从交付包删除。以下内容即使是“本地测试用”，也应由接收方重新生成：

- `APP_SECRET_KEY`
- `API_KEY`
- `ADMIN_PASSWORD`
- `POSTGRES_PASSWORD`
- `AVATAR_SERVICE_TOKEN`
- `PUBLISH_*_ACCESS_TOKEN`、`PUBLISH_*_REFRESH_TOKEN`
- `DOUYIN_CLIENT_SECRET`、`PUBLISH_*_CLIENT_SECRET`
- `ONEAPI_API_KEY`

处理方式：公司电脑从 `.env.example` 新建 `.env`，重新生成本地应用密钥和管理员密码；不要把开发机的值复制过去。

## B. 高概率属于公司业务或公司付费账户：先确认移交，不要擅自删除原账户

以下变量与公司云服务、公司控制层或公司旧网关有关，不能仅凭“在我的电脑上”就认定为个人：

- `DASHSCOPE_API_KEY`
- `ALIYUN_MODEL_STUDIO_WORKSPACE_ID`
- `ALIYUN_OSS_BUCKET`
- `ALIYUN_MPS_PIPELINE_ID`
- `ALIYUN_MPS_TEMPLATE_ID_720P`
- `ALIYUN_MPS_TEMPLATE_ID_1080P`
- `ALIBABA_CLOUD_ACCESS_KEY_ID`
- `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
- `COPYWRITING_API_KEY`
- `SHUYING_AVATAR_API_CODE`
- `VIDEOINSIGHT_CONTROL_PLANE_URL`
- `VIDEOINSIGHT_CONTROL_PLANE_ENABLED`
- `AVATAR_SERVICE_BASE_URL`

建议：公司重新创建或接管公司名下的密钥，验证成功后再撤销旧密钥。不要把个人云账号直接“转交”给公司，也不要在文档或聊天中发送密钥值。

## C. 高风险、归属待核实：优先按个人凭据处理

如果这些账号是用个人邮箱、个人银行卡或个人订阅购买的，应视为个人凭据，不应随源码交付：

- `MINIMAX_TOKEN_PLAN_KEY`
- `PEXELS_API_KEY`
- `PIXABAY_API_KEY`
- `VIDEO_IMAGE_API_KEY`
- `VIDEO_DIRECTOR_API_KEY`
- `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、其他个人模型供应商 Key

确认方法：查看供应商控制台的注册主体、账单主体、付款方式和团队成员；不要通过比较密钥字符串来判断归属。

## D. 个人电脑路径、浏览器和本地资产：不要带走

这些通常不是 API 密钥，但可能包含个人数据、登录态或无法在公司电脑复用的路径：

- `LOCAL_AVATAR_*`
- `SADTALKER_*`
- `*_BROWSER_DISCOVERY_PROFILE_DIR`
- `*_BROWSER_DISCOVERY_DEBUG_PORT`
- `DATABASE_PATH`
- 任何绝对路径、浏览器 profile、Cookies、下载目录、头像、声音和客户媒体

公司应在自己的电脑上重新配置路径，不应复制浏览器用户目录或登录会话。

## E. 当前审计证据与本次清除结果

- `.env` 中发现多组已配置值，但本文件不显示任何值；
- `scripts/scan_release_secrets.py` 已对本机配置进行比对，候选源码中未命中这些已配置供应商密钥值；
- 已按要求清空根目录 `.env` 中全部 `DASHSCOPE_*`、`ALIYUN_*`、`ALIBABA_CLOUD_*` 值；这些变量名仍保留为空，便于公司填写自己的配置；
- 已检查 `.env`、`.env.production`、`.streamlit/secrets.toml` 和当前进程环境，没有发现实际的 `DEEPSEEK_*` 密钥值；代码/测试中的 DeepSeek 字样不是密钥；
- `.streamlit/secrets.toml` 仍有 `DOUYIN_CLIENT_KEY`、`DOUYIN_CLIENT_SECRET`、`ONEAPI_API_KEY` 配置名，未被本次清除范围覆盖；
- 配置版交付 ZIP 生成后还要再次扫描压缩包内容；
- 这份清单不代表所有权判定，也不替代公司正式的密钥轮换和撤销流程。

## F. 最安全的移交顺序

1. 先交付脱敏源码包；
2. 公司在自己的密钥管理系统中创建新凭据；
3. 公司电脑用新凭据完成低成本功能验证；
4. 公司确认旧凭据不再需要后，由凭据所有者撤销或轮换；
5. 最后再处理开发机上的 `.env`、浏览器登录态和个人本地数据。
