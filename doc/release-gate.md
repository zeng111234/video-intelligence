# 上线门禁与交付范围

## 一键检查

开发中的工作区可以运行：

```powershell
.\scripts\check_release.ps1 -AllowDirty
```

正式交付前必须提交已经确认的改动，再运行：

```powershell
.\scripts\check_release.ps1
```

不带 `-AllowDirty` 时，只要工作区存在修改、删除或未跟踪文件，检查就会失败。这样可以保证测试结果对应一个明确的 Git 提交。

门禁会检查：

- 工作区是否干净；
- 是否误提交 `.env`、数据库、运行数据、媒体、模型或第三方参考副本；
- Git 空白错误和全仓 Python Ruff；
- 后端全量 pytest；
- 前端全量 Vitest、TypeScript 类型检查和生产构建。

门禁只运行本地测试，不调用付费生成、云转写、数字人供应商或真实发布接口。

## 交付范围

正式交付物以通过门禁的 Git 提交为唯一基线。朋友只需要拉取该提交并运行根目录的 `start.bat`。

以下内容不进入交付：

- `.env`、`.env.production` 和任何真实密钥；
- `data/`、`outputs/`、`uploads/`、模型、数据库和运行日志；
- 本地浏览器资料、Cookie、二维码和验证码；
- `forge_rss_analysis/`：它是用于安全分析的 ForgeRSS 第三方参考副本，产品运行没有依赖；
- 本地测试生成的媒体和下载文件。

## 必须单独授权的真实验收

下列项目无法由无副作用自动化代替。执行前必须准备专用账号、预算上限和回滚方案，并再次取得明确确认：

- AI 文案、云转写、数字人、云剪辑等可能扣费的提交；
- 抖音等平台的扫码登录、验证码和真实发布；
- 充值审批、客户充值、禁用客户、管理员密码重置；
- 删除、批量删除及其他不可逆数据操作。

专项验收应记录预计费用、实际费用、任务编号、供应商最终状态和恢复方式。`OUTCOME_UNKNOWN` 只能查询或人工核对，不能直接重新付费提交。

## 正式交付步骤

1. 用 `git diff` 审核本次上线范围，确认删除文件确实不再需要。
2. 提交全部预期代码、迁移和测试，不混入本机数据与参考仓库。
3. 运行 `.\scripts\check_release.ps1`，必须得到 `[PASS]`。
4. 从该提交重新拉取或打包，使用 `start.bat` 做一次全新启动验收。
5. 再按上面的授权边界执行真实账号和付费专项验收。
