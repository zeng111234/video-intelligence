## 1. 核心问题或目标

**核心问题**：当前爬虫系统虽然采用了"本机 Chrome + 用户手动登录"的安全基线，但缺少反检测指纹伪装、代理IP轮换、请求头随机化、浏览器自动化特征隐藏等关键防护层，在抖音/小红书等高反爬平台上仍有较高封号风险。

**目标**：在不大幅重构现有架构的前提下，分阶段补齐反爬安全层，将封号率从当前估计的 40%-80% 降低到 10% 以下。

---

## 2. 现状审查：已有的安全措施

### 2.1 已有安全措施（做得不错的部分）

| 措施 | 涉及文件 | 说明 |
|------|----------|------|
| 本机 Chrome 专用 Profile | douyin_browser_search.py, platform_browser_search.py | 每个平台独立隔离的浏览器资料目录，避免跨平台 Cookie 串扰 |
| 用户手动登录 | 全部浏览器适配器 | 不自动破解登录，由操作者扫码登录后复用登录态 |
| 随机延迟 | douyin_browser_search.py (L66-69) | 页面加载 3.5-5.5s，搜索 3-5s，滚动 0.45-0.85s |
| 请求频率限制 | crawler.py (L105-129) | 每平台 24h 内最多 4 次真实采集，冷却 1h，安全暂停 24h |
| 登录态检测 | platform_browser_search.py (L97-98) | 检测安全验证访问频繁等标记，触发时自动停止 |
| B站 API 请求头 | bilibili_public_search.py (L229-243) | 设置了标准浏览器 User-Agent、Referer、Origin |
| 不下载媒体 | 全部适配器 | 只读取元数据，不下载视频/图片，降低触发风险 |

### 2.2 缺失的安全措施（需要补齐的部分）

| 缺失措施 | 风险等级 | 说明 |
|----------|----------|------|
| **反自动化特征隐藏** | **高** | 未设置 --disable-blink-features=AutomationControlled，Playwright CDP 连接特征容易被检测 |
| **navigator.webdriver 隐藏** | **高** | 未注入反检测 JS，navigator.webdriver 属性暴露自动化身份 |
| **代理IP轮换** | **高** | 所有请求来自同一 IP，频繁访问同一平台容易触发 IP 封禁 |
| **User-Agent 随机化** | **中** | B站 API 使用固定 UA，浏览器适配器使用默认 Chrome UA |
| **请求间隔随机化不足** | **中** | 浏览器操作延迟范围偏短（0.45-0.85s），真实用户滚动间隔通常 1-3s |
| **TLS 指纹伪装** | **中** | B站 API 使用 httpx 默认 TLS 指纹，可能被识别为非浏览器客户端 |
| **登录态自动续期** | **中** | 无自动检测登录过期并提醒重新登录的机制 |

## 3. 风险等级评估

### 3.1 各平台封号风险

| 平台 | 反爬等级 | 当前封号风险 | 主要风险点 | 改进后预期风险 |
|------|----------|--------------|------------|----------------|
| 抖音 | 最高（Level 3+） | **60%-80%** | 无指纹隐藏、无代理、Playwright CDP 特征明显 | <10% |
| 小红书 | 高（Level 3+） | **50%-70%** | 需要登录态、无代理、验证频繁 | <15% |
| 快手 | 中高（Level 3） | **40%-60%** | 无代理、请求特征明显 | <10% |
| B站 | 中（Level 1） | **20%-40%** | API 直连、无 TLS 指纹伪装、固定 UA | <5% |

### 3.2 与 ForgeRSS 方案对比

| 维度 | 你的项目 | ForgeRSS | 差距 |
|------|----------|----------|------|
| 浏览器工具 | Playwright (CDP) | DrissionPage (CDP) | DrissionPage 反检测更强 |
| 反自动化隐藏 | 无 | --disable-blink-features=AutomationControlled + 其他参数 | **缺失** |
| 登录态管理 | 手动登录 + Profile 目录 | 持久化 Profile + login_checker 自动检测 | 差距不大 |
| 多引擎降级 | 无 | curl_cffi -> Selenium -> DrissionPage 三级降级 | **缺失** |
| 代理支持 | 无 | 无（ForgeRSS 也没做） | 持平 |
| 反爬等级分级 | 无 | 0/1/2/3+ 四级自适应 | **缺失** |

### 阶段二：中等加固（1-2周，难度中等）

**目标**：解决 IP 层面和 TLS 层面的识别风险。

**难度**：中等
**AI辅助时间**：3-5天
**预期效果**：封号率降低 20%-30%

#### 4.2.2 B站 API 改用 curl_cffi

**涉及文件**：src/adapters/bilibili_public_search.py

**原因**：httpx 的 TLS 指纹与真实浏览器差异大，curl_cffi 可以模拟 Chrome 的 TLS 指纹。

**难度**：中等
**AI辅助时间**：2-3天
**预期效果**：B站封号率从 20%-40% 降低到 <5%

#### 4.2.3 User-Agent 随机化

## 6. 验证步骤

### 6.1 阶段一验证

1. **参数验证**：启动浏览器后在 chrome://version 页面确认启动参数生效
2. **指纹验证**：访问 https://bot.sannysoft.com/ 检查自动化特征是否被隐藏
3. **webdriver 验证**：在浏览器控制台执行 navigator.webdriver，应返回 undefined
4. **功能验证**：执行一次完整搜索流程，确认结果正常返回

### 6.2 阶段二验证

1. **代理验证**：检查每次请求是否使用了不同的出口IP
2. **TLS 验证**：使用 Wireshark 对比 httpx 和 curl_cffi 的 TLS ClientHello 差异
3. **压力测试**：在测试账号上连续执行 10 次搜索，观察是否触发验证码
4. **封号测试**：使用测试账号运行 7 天，统计封号率

### 6.3 阶段三验证

1. **DrissionPage 验证**：对比 Playwright 和 DrissionPage 在 bot.sannysoft.com 上的得分
2. **登录态验证**：模拟登录过期场景，确认系统能正确检测并通知
3. **自适应验证**：在不同反爬等级的网站上测试，确认策略选择正确
4. **长期稳定性测试**：连续运行 30 天，统计封号率和采集成功率

## 7. 结论

### 7.1 主要发现

1. **当前安全基线是合理的**：本机 Chrome + 用户手动登录 + 频率限制，这个架构方向是对的
2. **缺失的是纵深防御的上层**：反检测指纹、IP轮换、TLS伪装等防护层还没有
3. **最大的风险是 Playwright CDP 特征暴露**：抖音等平台可以检测到 Playwright 的连接特征
4. **ForgeRSS 的方案可以参考但不需要照搬**：DrissionPage 可以引入作为备选，但不需要替换整个架构

### 7.2 优先级建议

1. **立即做**（1天内）：阶段一，零成本，效果显著
2. **尽快做**（1周内）：阶段二，需要代理IP服务投入
3. **按需做**（1个月内）：阶段三，如果阶段一二效果不够再推进

### 7.3 成本收益分析

| 投入 | 收益 |
|------|------|
| 1.5天开发时间 | 封号率降低 30%-55% |
| +500-2000元/月代理费 | 封号率再降低 20%-30% |
| +2-3周开发时间 | 封号率降到 <10% |

**建议**：先用 1.5 天完成阶段一，观察效果后再决定是否投入阶段二和三。
